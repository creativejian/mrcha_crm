# 앱 팀 요청 — 전화번호 유일성 확보 (휴대폰 인증 로그인 전환의 전제 작업)

작성: 2026-07-26 CRM(유슨생 세션) · 전달: 유슨생 → 앱 팀
근거: 실 master DB 실측(아래 §2 — 문서 인용이 아니라 2026-07-26 당일 조회)

## 1. 요약

**같은 전화번호로 앱 계정이 여러 개 생길 수 있고, 실제로 생겨 있습니다**(현재 5계정 — 전부
이사님 테스트라 실피해 0). 카카오·구글 로그인은 유지하고 이메일 로그인을 **휴대폰 인증
로그인으로 교체**할 계획이라 들었는데, 그 전환은 **번호 → 계정 1:1**이 전제입니다(번호로
계정을 찾아야 하므로). CRM도 같은 불변식이 필요합니다 — 중복 계정이 각각 견적요청을 내면
같은 사람이 CRM 고객 N명으로 분화됩니다(실사례: 김지안 번호 계정 3개 = 고객 3명
CU-2605-0020·CU-2606-0001·CU-2607-0002).

CRM이 원하는 불변식은 한 줄입니다: **"인증된 번호는 어느 시점에든 최대 1계정"**.
구현 방식은 앱 팀 소관이고, 아래는 실측과 제안·열린 질문입니다.

## 2. 실측 (2026-07-26, 실 master DB)

- **중복 현황**: `01095880812` → 계정 3개(전부 phone_verified_at 보유 — vonage 2·solapi 1),
  `01099297324` → 계정 2개. 이외 중복 없음.
- **실증**: 2026-07-16에 세 번째 계정이 같은 번호로 solapi 인증에 **성공**했고, 기존 두 계정의
  번호는 그대로 남았습니다. 즉 중복 유입은 현재도 열려 있습니다.
- **차단 장치 부재(4층 전부 확인)**: ①`profiles.phone_number` UNIQUE 없음(형식 CHECK만)
  ②배포된 `complete_phone_verification`(실 DB 함수 본문 확인)에 타 계정 번호 회수/차단 없음
  ③인증 슬롯 거절 사유는 rate-limit 4종뿐 ④Flutter 인증 화면(required_authentication_screen)에
  기존 번호 체크 없음 — 앱 레포 최신(07-25) 기준.
- **잘 되고 있는 것**: 상담신청 폼 번호 = 인증된 프로필 번호 강제(최근 10건 전부 일치 실측) ·
  SMS 실소유 인증. 즉 "임의 번호 입력"과 "타인 번호 도용"은 막혀 있고, **"본인 번호로 계정
  여러 개"**(카카오 계정 갈아타기·재가입)만 열려 있습니다.

## 3. 제안 로드맵 (순서가 중요합니다)

1. **회수 규칙("새 인증이 이긴다")** — `complete_phone_verification`에서 인증 성공 시 같은
   번호를 가진 **다른 계정의 phone_number/phone_verified_*를 회수(null)**. 같은 트랜잭션
   안이라 UPDATE 추가 수준입니다. **회수 발생 여부를 반환값(예: 'verified_moved')으로 동봉**해
   주세요 — 클라가 "기존 계정에서 번호를 옮겨왔어요. 기존 계정의 견적·상담 이력은 그 계정에
   남습니다" 안내 1장을 띄우는 데 씁니다(추가 왕복 0).
   ⚠️ **사전 체크(SMS 발송 전 "이미 가입된 번호" 표시)는 지양** 권장 — 인증 전 노출이라 임의
   번호로 가입 여부를 조회당합니다(enumeration). 통보는 인증 성공 **후**가 안전합니다.
2. **기존 중복 5건 정리** — 휴대폰 로그인 전환 **전 필수**입니다(번호 lookup이 모호해짐).
   전부 이사님 테스트 계정이라 실사용자 영향 0. 어느 계정을 살릴지 기준만 정하면 됩니다
   (예: 최신 인증 승자 = ①과 같은 규칙).
3. **UNIQUE 제약(부분 인덱스, phone_number IS NOT NULL)** — ② 완료 후에만 가능(현재는 중복
   때문에 생성 실패). 동시 인증 레이스까지 막는 안전핀으로, 휴대폰 로그인의 최종 방어선.
4. **휴대폰 로그인 lookup 규칙** — 번호 입력 → SMS 인증 → **프로바이더 무관하게 그 번호를
   보유한 계정으로 로그인**(카카오로 만든 계정이라도). 여기서 신규 계정을 만들면 중복이
   재발합니다.

## 4. 열린 질문 (앱 팀 답 필요)

- **Q1. 회수 규칙 vs 휴대폰 로그인 키 충돌**: 휴대폰 로그인으로 만든 계정 B의 번호를, 나중에
  카카오 계정 A가 재인증하면 — ①의 회수 규칙대로면 **B는 로그인 수단을 잃습니다**(락아웃).
  이 경우만 ⓐ회수 대신 차단("이 번호는 휴대폰 로그인 계정에 사용 중") ⓑ계정 통합 플로우
  ⓒ그래도 회수(B는 다른 로그인 수단 연결 유도) — 어느 쪽으로 갈지. (카카오·구글 계정의
  번호는 "속성"이라 회수 무해, 휴대폰 로그인 계정의 번호는 "키"라는 비대칭이 논점입니다.)
- **Q2. ② 정리 시 승자 기준** — 최신 인증? 특정 계정 지정?(김지안 3계정 중 실사용 계정)
- **Q3. 시기** — 휴대폰 로그인 전환 일정과 ①~③의 순서 배치.

## 5. CRM 쪽 영향·계획 (참고)

- **회수가 CRM 화면에 미치는 영향**: 앱 연결 고객의 표시 연락처는 profiles 합성(read-through,
  2026-07-17 #276 계약)이라, 회수당한 계정에 연결된 CRM 고객은 **연락처 표시가 사라집니다**.
  이는 "번호 주인이 바뀌었다"는 정확한 신호라 CRM은 수용합니다(별도 요청 없음). 다만 ② 정리
  시점에 어떤 고객의 표시가 비는지는 CRM이 사전 확인하겠습니다.
- **CRM은 별도로**(앱 작업과 무관하게) 인박스 승격/연결 시 **같은 번호의 기존 고객 경고**를
  추가할 예정입니다 — 연결 고객의 합성 번호까지 대조해, 회수 규칙 도입 전 유입과 레거시
  중복이 새 고객으로 분화되는 것을 상담사 시점에서 차단합니다.
- 이미 분화된 CRM 고객 3명(김지안)은 번호 정리와 무관하게 남습니다 — CRM에서 수동 정리
  (병합 기능 없음, admin 삭제 + 연결 재작업)할 문제이고 테스트 데이터라 급하지 않습니다.
