즉 그쪽 11건 표 안에 있고, ②(b)의 비결정 폴백 경로는 **저희와 무관**합니다.

**`masterMcCode`는 구조적으로 항상 실립니다.** 저희 차량 픽커가 `mcCode`가 없는 트림을

그래서 `masterMcCode` 없이 나가는 호출은 만들어질 수 없습니다.

참고로 저희 쪽에 `lender = "iM캐피탈"` 시나리오가 4건 더 있지만 **전부 수기 입력**이라 그쪽 API를 안 탔습니다.

## ③ `QT-2607-0012` 요청 페이로드

A 정정 후 확정 월 납입금 계산에 쓰시라고 저희가 보낸 값 그대로 붙입니다.

```jsonc
{
  "lenderCode": "im-capital",
  "productType": "operating_lease",
  "brand": "BMW",
  "modelName": "5 Series",
  "masterMcCode": "MC070526006",
  "quotedVehiclePrice": 74300000,   // 할인 전(base 74,300,000 + option 0)
  "discountAmount": 0,
  "evSubsidyAmount": 0,
  "ownershipType": "company",
  "leaseTermMonths": 60,
  "annualMileageKm": 20000,
  "depositAmount": 0,
  "upfrontPayment": 0,
  "residualMode": "high"
}
```

딜러명은 미지정, CM/AG 수수료는 분율 0 상시 전송입니다. 그쪽 응답의 `majorInputs`
(`depositAmount 0` / `upfrontPayment 0` / `leaseTermMonths 60` / `ownershipType company`)와 일치했고 —
**A 이전의 차이는 `vehiclePrice` 하나뿐**이었습니다(74,300,000 → 69,800,000).
**A 반영 후 재계산에서 그 차이가 사라진 것**을 위 「먼저」 절에 실측으로 정리했습니다.

## ④ 응답 필드(D) 의견 — 한 필드만 더 부탁드립니다

제안하신 3필드에 찬성합니다. **다만 B를 하고 나면 이번 사고를 잡던 신호가 죽습니다.**

지금 이 사고가 드러나는 이유는 `priceSource: "catalog"`이기 때문인데, B에서 iM이 `quotedVehiclePrice`를
읽도록 고치면 **가격은 항상 저희 값으로 덮이므로** 링크가 엉뚱한 offering을 가리켜도 가격에 흔적이
남지 않습니다. `matchedBy`도 여전히 `master_mc_code`(=exact)일 거고요. **B 이후엔 같은 사고가 조용해집니다.**

그래서 **매칭된 offering의 카탈로그 가격**을 항상 함께 실어 주시면 좋겠습니다:

```jsonc
"resolvedVehicle": {
  "modelName": "The New 5 Series 520i M Sport Package (P1) #116604-1054542",
  "matchedBy": "master_mc_code",   // master_mc_code | model_name | vehicle_key
  "requestedPrice": 74300000,      // 저희가 보낸 quotedVehiclePrice 에코
  "catalogPrice":   74300000,      // ← 추가 요청: 매칭된 offering 자체의 가격
  "vehiclePrice":   74300000,      // 실제 계산에 쓴 값
  "priceSource": "request"         // request | catalog
}
```

`requestedPrice ≠ catalogPrice` → **링크 오배정**. 이게 B 이후에도 살아남는 유일한 축입니다.
이번 건이면 `requested 74,300,000` vs `catalog 69,800,000`으로 **B와 무관하게** 잡혔을 겁니다.

나머지는 그대로 좋습니다:
- `matchedBy: "vehicle_key"` → 저희는 **비결정 경로로 보고 견적을 거부**하겠습니다(⑦ 다중 매칭도 같은 성격).
- `requestedPrice` 에코 → 로그 대조에 유용합니다.

### ⚠️ 다만 요청 규모를 정정드립니다 — 저희가 그쪽 코드를 확인했습니다

`catalogPrice`를 "필드 하나 추가"로 가볍게 말씀드렸는데, `resolveMasterMcCodeToOffering`
(`src/domain/imports/catalog-queries.ts`)이 지금 돌려주는 건 **`lenderBrand`·`lenderModelName`
두 개뿐**이고 **가격은 select에 없습니다.** 그 위에서 offering 가격을 다시 찾는 구조라면,
저희 요청은 응답 조립만이 아니라 **조회 경로를 넓히는 일**이 됩니다.

그래서 이렇게 정리하고 싶습니다:

- **급하지 않습니다.** ⑤의 저희 가드가 `majorInputs` 축으로 이미 돌고 있어서 **지금 당장은 공백이 없습니다.**
- 부담되시면 **`catalogPrice` 없이 `requestedPrice` + `priceSource`만 먼저** 가셔도 됩니다.
  다만 그 2필드만으로는 **B 완료 후 링크 오배정을 못 잡는다**는 점만 기억해 주시면 좋겠습니다
  (B 후엔 `priceSource`가 항상 `request`가 되니까요).
- `matchedBy`는 저희가 `vehicle_key` 판별용으로만 쓸 생각이라 **없어도 무방**합니다.

> 갱신본 조치표에 `catalogPrice`가 없어서 반려인가 했는데, 코드를 보니 **D 자체가 아직 착수 전**이라
> (`requestedPrice`·`priceSource`·`matchedBy`·`catalogPrice` 모두 미검출) 순서상 자연스러운 상태로
> 이해했습니다. 형태부터 합의하자는 뜻으로 받아들이고, 위 우선순위를 의견으로 드립니다.

## ⑤ 저희 쪽 조치 — 가드 배포 완료(축 하나 바꿨습니다)

**1. 응답 가드를 그쪽 배포를 기다리지 않고 이미 붙였습니다.** 다만 처음 말씀드린
`resolvedVehicle.vehiclePrice`가 아니라 **`majorInputs.vehiclePrice`(실제 계산에 쓴 값)**를 봅니다.
D를 설계하실 때 참고가 될 것 같아 이유를 공유드립니다.

갱신본 ③을 읽고 축을 바꿨습니다. **산은은 마스터↔offering 카탈로그가 불일치가 정상**이고(재배정
대상도 아니라고 하셨죠), 산은 엔진은 `quotedVehiclePrice`를 우선하니 **그 불일치가 견적가에 영향을
주지 않습니다.** 그런데 카탈로그가로 대조하면 산은 i5·iX1 견적마다 헛경고가 뜹니다 — 저희 표본에
그 차종이 없어 실측으로는 안 걸렸을 뿐, **오탐이 예정돼 있었습니다.**

실제 계산 입력을 보니 **금융사 제한도 필요 없어졌습니다.** "우리가 보낸 가격으로 계산했는가"는
8사 모두에게 같은 질문이고, 그쪽 표대로면 iM 외에는 전부 저희 값을 쓰니까요. 카탈로그가 축이
아니라서 MG·메리츠·우리카드의 94~96% 불일치와도 무관합니다.

검증: 실 응답 6건 중 사고 건만 발화 → **A 반영 후 재계산에서는 조용**(위 「먼저」 절 값).
산은 오탐 시나리오(계산=저희 값 84,900,000 / 카탈로그 92,800,000)도 조용한 것을 확인했습니다.

> 이 축은 **B가 끝나면 자연히 조용해집니다** — 그게 정상입니다. 다만 그 뒤로는 "링크는 엉뚱한데
> 가격만 저희 값으로 덮인" 상태를 못 잡습니다. ④의 `catalogPrice`를 부탁드린 게 그래서입니다.
> **산은 8건(F)이 정리되기 전에는 카탈로그가 축을 켤 수 없다**는 점도 함께 봐 주시면 좋겠습니다 —
> 그 둘은 같이 와야 의미가 있습니다.

**2. `QT-2607-0012` 재발송은 하지 않습니다** — 위에 적은 대로 내부 테스트 데이터였습니다.

**3. 별건 픽스 하나 공유**: 잔존이 `max`일 때 고객 카드에 그쪽 응답의 금액·율 대신 "최대"라는
문구만 나가던 버그를 고쳤습니다. 이제 **그쪽 값을 그대로** 표시합니다 — A 반영 후 재계산 기준으로
`44,580,000원 (60%)`입니다.
→ **즉 그쪽 응답이 어긋나면 그대로 고객에게 갑니다.** 저희가 대조 가드를 급히 붙인 이유입니다.
